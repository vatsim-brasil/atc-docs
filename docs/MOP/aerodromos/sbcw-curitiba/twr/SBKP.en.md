## :material-routes: Runways

### Preferential runway system

SBKP has **one runway**, 15/33 (3240 × 45 m, asphalt). **C** runs along the runway end to end, between it and the aprons; **G** runs parallel to C in front of apron 3 and links the new aprons (4 to 6) with the middle of the aerodrome.

<div class="grid cards" markdown>

-   :material-airplane:{ .lg .middle } **Preferential: `15`**

    ---

    Landings and takeoffs. ILS CAT I.

-   :material-airplane:{ .lg .middle } **Alternative: `33`**

    ---

    Used when the wind rules out 15. Non-precision approaches only (RNP and VOR). Threshold displaced by 90 m.

</div>

!!! warning "Preferential system"
    With {==**a tailwind component below 7 kt**==} and a **dry runway**, the runway in use is **15**[^ad20-2].

    With 15 in use and a tailwind, pilots who request 33 should expect a **delay** in landing or takeoff[^ad20-2].

### Runway data

| Runway | Dimensions | TORA | LDA | Approach | Remarks |
| :---: | :---: | :---: | :---: | :---: | :--- |
| **15** | 3240 × 45 m | 3150 m | 3150 m | ILS CAT I | |
| **33** | 3240 × 45 m | 3240 m | 3150 m | Non-precision | RNP and VOR. Displaced threshold (90 m) |

- The AD accepts aircraft up to code **4E**. The **B747-8** operates under special procedures[^ad20-5].

[^ad20-2]: [AIP Brasil, AD 2 SBKP 2.20, item 2](https://aisweb.decea.mil.br/?i=publicacoes&p=aip). Declared distances: AD 2.13.
[^ad20-5]: [AIP Brasil, AD 2 SBKP 2.20, item 5](https://aisweb.decea.mil.br/?i=publicacoes&p=aip).

## :material-headset: ATC Units

| Code | Abbr. | Callsign | Frequency | Remarks |
| :--- | :---: | :--- | :---: | :--- |
| **SBKP_ATIS** | `AKP` | Campinas Information | **127.825** | D-ATIS |
| **SBKP_DEL** | `DKP` | Campinas Clearance | **121.100** | `DCL` (code `SBKP`) |
| **SBKP_GND** | `GKP` | Campinas Ground | **121.900** | |
| **SBKP_TWR** | `TKP` | Campinas Tower | **118.250** | |

### Departure communications

1. The pilot calls Clearance or sends the DCL request **no earlier than 15 min before EOBT**[^ad20-1].
2. Each contact is made on that position's frequency: Clearance, Ground and Tower[^ad20-1].
3. On handoff to Tower, Ground instructs the pilot to **monitor Tower**, with no initial call. The aircraft waits for Tower's call, ready for an immediate departure[^ad20-1].
4. Tower does not give the takeoff time. The aircraft stays on Tower until crossing the opposite threshold or starting the turn, then calls APP with only `SÃO PAULO CONTROL, [CALLSIGN]`[^ad20-1].

### DCL

SBKP has **DCL** (departure clearance via datalink)[^ad18]. On the network, the station code is **`SBKP`**.

| | |
| :--- | :--- |
| **Station code** | `SBKP` |
| **Who operates it** | SBKP_DEL. Without DEL, the position covering clearance top-down (GND, TWR, APP or ACC) |
| **Controller tool** | TopSky DCL window, with your personal Hoppie ACARS code |
| **Pilot tool** | Aircraft ACARS or a Hoppie-compatible client, sending the clearance request to `SBKP` |

**How it works:**

1. The pilot sends the request (RCD) to `SBKP`, with the parking stand and ATIS letter.
2. The controller checks the flight plan and replies with the clearance: limit, runway, SID, transponder code, ATIS letter and next frequency.
3. The pilot accepts (`WILCO`/`ACCEPT`). The clearance is then issued and **there is no voice readback**.
4. With the clearance accepted, the pilot calls Ground for start-up or pushback.

!!! tip "Controller setup"
    - Log in to the TopSky DCL with the code `SBKP` before opening the position.
    - Announce it in the controller information: `DCL AVBL LOGON SBKP`.
    - A faulty request (invalid plan, wrong SID, no ATIS) goes back as **REVERT TO VOICE**: the pilot calls Clearance on frequency.
    - If the pilot does not accept within a reasonable time, consider the clearance not delivered and call them by voice.

[^ad18]: [AIP Brasil, AD 2 SBKP 2.18](https://aisweb.decea.mil.br/?i=publicacoes&p=aip).

  ![Map of SBKP with the runway strip in yellow, under Tower, and the rest in blue, under Ground](img/sbkp-responsabilidade.svg){ loading=lazy }
  <figcaption>Yellow strip: Tower. Rest: Ground. The dashed line runs through the holding points. White circles: apron numbers.</figcaption>

| Position | Responsible for |
| :--- | :--- |
| **GND** | Aprons 1 to 6, TWY **C**, **G** and the links up to the **holding point** |
| **TWR** | Runway 15/33 and the TWY inside the holding points |

- SBKP **has no Apron position** (APRON): Ground handles all aprons.
- **Departures:** Ground hands off to Tower (monitor) **before the holding point**. Pilots reach the holding point ready for departure; if not, they tell Ground[^ad20-3].
- **Arrivals:** after vacating the runway, Tower hands off to Ground.

## :material-transit-connection-variant: Ground flow

!!! abstract "General rule"
    - **C** runs along the runway and reaches both thresholds: via **D** at 15 and via **E** at 33.
    - **G** runs between C and apron 3. **K1** and **K2** link G with aprons 4, 5 and 6 (passenger terminal); **L1** and **M** go around those aprons on the west side to D.
    - **J**, **J1** and **K** link C with aprons 1 and 2. **E1** leads to the hangar next to threshold 33.
    - **A**, **B** and **F** are the rapid exits; **H** is the runway 15 intersection departure.
    - Aprons are always left with **pushback**[^ad20-5].

=== "Runway 15"

    <figure markdown="span">
      ![Ground flow on runway 15: departures via K1, G and H; code D/E via D; landings vacate via A or B and return along G to apron 4](img/sbkp-fluxo-15.svg){ loading=lazy }
      <figcaption>Green: departures. Dashed orange: threshold departure (code D/E) and exit via F. Blue: landings.</figcaption>
    </figure>

    - **Departures (15), code A/B/C:** **K1**, **G**, **C** and **H** (TORA 2910 m)[^ad20-3].
    - **Code D/E:** full length, via **L1**, **M** and **D** to the threshold.
    - **Landings (15):** vacate via **A** (1100 m) or **B** (1570 m) and return along **G** to aprons 4 to 6. Code C/D may also vacate via **F** (2200 m)[^ad20-3].

    Example: `AZU4321, taxi to holding point runway 15 via K1, G, C and H.`

=== "Runway 33"

    <figure markdown="span">
      ![Ground flow on runway 33: departures via G and C to E; code A/B from F; landings vacate via B](img/sbkp-fluxo-33.svg){ loading=lazy }
      <figcaption>Green: departures. Dashed orange: intersection departure (code A/B). Blue: landings.</figcaption>
    </figure>

    - **Departures (33):** **K1**, **G** and **C** to **E** (threshold 33).
    - **Code A/B:** departs from **F** (TORA 2208 m)[^ad20-3].
    - **Landings (33):** up to code C, vacate via **B** (1350 m)[^ad20-3].

    Example: `GLO1234, taxi to holding point runway 33 via K1, G, C and E.`

### Runway exits

Pilots must vacate the runway **completely** before stopping, via the listed exit, or tell APP or Tower if they cannot use it[^ad20-3].

| Runway | Who | Exits |
| :---: | :--- | :--- |
| **15** | Category A and B | **A** (1100 m) |
| **15** | Category C and D | **A** (1100 m), **B** (1570 m) or **F** (2200 m) |
| **33** | Up to category C | **B** (1350 m) |

### Hotspots

| Hotspot | Where | Watch out |
| :---: | :--- | :--- |
| **HS1** | **M** with **L1** | Complex intersection when taxiing along M towards 15 |
| **HS3** | **A** and **B** with **C** | Complex intersection between the rapid exits and C |
| **HS5** | **G** in front of apron 3 | Pushbacks from stands M01 to M08 and N107 |
| **HS6** | **F** | Rapid exit |

### Taxi restrictions

| Restriction | Where |
| :--- | :--- |
| **Pushback required** | Leaving any apron[^ad20-5] |

## :material-speedometer: HIRO and reduced separation

With **HIRO** (high-intensity runway operations) active on the **ATIS**, pilots plan landing and takeoff for the minimum runway occupancy time[^ad20-3].

| | |
| :--- | :--- |
| **Approach speed** | **150 to 170 kt** at 5 NM from the threshold; then slow down to approach speed. ATC-assigned speeds are mandatory[^ad20-1] |
| **Landing** | Vacate the runway **completely** before stopping, via the exit listed in the runway exits table |
| **Takeoff** | Request through DCL; code A/B/C from **H** (15), code A/B from **F** (33) |

!!! info "RRSM: reduced runway separation minima"
    Tower may apply reduced separation between landings and departures when all of the conditions below hold and RRSM is on the **ATIS**[^ad20-4]:

    - wake separation respected;
    - visibility of **5 km** or more and ceiling of **1000 ft** or more;
    - tailwind up to **3 kt** and an uncontaminated runway.

    The preceding aircraft must have passed **2400 m** from the threshold in use. For landing after landing, it must also be moving and vacating the runway without backtracking.

    Example: `AZU4321, cleared to land runway 15, wind 180 degrees 6 knots. A320 ahead departing.`

    :material-weather-sunny: **Note:** the AIP only provides for RRSM by day, from 30 min after sunrise to 30 min before sunset.

[^ad20-1]: [AIP Brasil, AD 2 SBKP 2.20, item 1](https://aisweb.decea.mil.br/?i=publicacoes&p=aip).
[^ad20-4]: [AIP Brasil, AD 2 SBKP 2.20, item 4](https://aisweb.decea.mil.br/?i=publicacoes&p=aip).
